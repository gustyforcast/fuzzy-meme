## Register Maintenance

- Add a new row whenever a design discussion surfaces an unresolved question with real consequence — don't let it live only in a conversation or commit message.
- Close a row by updating Status to **Resolved** with a one-line note on the outcome and a link/reference (e.g., "Resolved — SwiftData chosen, see ARCHITECTURE.md § 5 rev 2") rather than deleting it — a resolved-risk history is useful context for v2 decisions.
